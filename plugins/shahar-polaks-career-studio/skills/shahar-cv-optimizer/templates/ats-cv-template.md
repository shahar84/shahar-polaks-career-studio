# ATS content template

Use this as the content backbone for all CV themes. Read [persona guidance](../references/candidate-personas.md) and adapt section order before filling it. Read [worked examples](../references/worked-examples.md) for evidence limits. Instructions and bracketed slots below are authoring aids; remove them from the finished CV.

## Name and contact details

[Candidate's supplied name]
[Relevant city/country if supplied] | [Email] | [Phone if supplied] | [Supplied LinkedIn or portfolio links]

Use only supplied contact details. Do not invent a URL or full address. A role-focus line may describe supported professional identity; identify a target title as a target when it is not a title held.

## Professional Summary

Use two to four concise lines when they add positioning beyond the role titles. Connect the supported professional focus, relevant scope or strongest evidence, and stated target direction. Omit a generic summary that adds no information. Do not write an aspirational title as an existing role.

## Experience

**[Exact role] | [Employer] | [Dates as supported]**

[Optional one-line scope statement, only if supplied and useful.]

- [Personal action] + [specific context or scope] + [supported result, if known].
- [Next distinct role-relevant contribution].

Use three to five useful bullets for the most relevant recent role when evidence supports them; use fewer for older or less relevant roles. Do not fabricate bullets to meet a count. Keep reverse chronology and distinguish promotions, concurrent roles, and employment gaps accurately. Retain original titles; clarify responsibilities separately.

## Selected Projects

Include for junior or switching candidates, or when a project adds evidence missing from employment. Move this above Experience when it is the strongest direct evidence for the target.

**[Project name] | [Personal, academic, volunteer, or commercial context] | [Dates or link if supplied]**

- [What the candidate personally built or did, using supported tools].
- [Demonstrable behavior, test, deployment, or outcome if supplied].

Never relabel a personal project as paid work, a course as employment, or a prototype as a production system. Remove this section when irrelevant.

## Skills

Group only relevant supported skills into readable lines, for example languages, systems, data, or leadership practices. Use groups that fit the candidate. Preserve distinctions such as production use, basic exposure, or hands-on administration when material. Do not add a target posting's tools to satisfy keywords.

## Education and Certifications

**[Verified qualification or training] | [Institution] | [Dates or status if supplied]**

Distinguish a completed degree, course, certification, and qualification in progress. Preserve the supplied credential level. Remove unsupported dates and irrelevant school detail instead of filling gaps.

## Optional additional evidence

Add public speaking, publications, community work, languages, or relevant service only when supplied, useful, and appropriate to the request. Do not borrow the reference PDFs' optional sections by default.

## Final copy boundary

The candidate document contains only the finished sections and facts. Put template selection, changes made, and unresolved confirmation questions in the assistant's accompanying response. Never leave bracketed slots, sample names, plugin branding, or `Requires confirmation` inside a submission-ready CV.
