# PDF and document design guidelines

Use the [template index](../templates/template-index.md) to select the content structure and visual theme. Classic is the default. Honor an explicit Crimson or Warm choice without requiring a prior Classic document or approval.

## Use the actual reference

Read the selected style specification and inspect both pages of its linked PDF before reproducing that design. Use the host's PDF skill or tools to render and view pages; text extraction alone does not establish visual fidelity. The reference PDFs contain fictional sample facts. Copy only visual structure, never names, employers, dates, technologies, claims, metrics, or contact details.

If the PDF cannot be accessed or rendered, proceed from its written specification and tell the user outside the CV that the visual reference could not be checked. Do not claim an exact reproduction. If a requested font is unavailable, use a readable installed substitute and disclose a material visual difference when relevant. Do not claim a font is embedded or licensed without checking.

## Shared layout requirements

- Start from A4, 48 pt left and right margins, and a white background, matching the bundled references. Adapt to a requested page size without shrinking text to force a page count.
- Keep one main content column. Date gutters and right-aligned metadata are optional and must preserve role/date association and logical text extraction. If they cannot, place dates and contact details inline.
- Use the selected theme's name, heading, body, and accent hierarchy. Body text should normally be 10.5-11 pt with comfortable leading. The reference's smaller type is a visual guide, not a reason to compromise readability.
- Keep a heading with at least its first entry, a role with its first bullet, and a short bullet together. Prefer a deliberate page break between roles to a crowded bottom margin.
- Choose one or two pages according to relevant evidence; the sample's two-page distribution is not mandatory. Compress older experience before shrinking type.
- Keep all essential contact details and career content in the body. A footer may contain page numbering or a redundant candidate name, but never the only contact details or plugin branding.
- Use real text and selectable bullets. Do not turn the CV into a flattened image or use rating bars, charts, icons, portraits, or decorative content tables.
- Include only candidate-requested, relevant optional sections. The samples' military-service or interests sections are not required fields.

## Verify the final artifact

For the packaged creation path, follow [document export](document-export.md). It uses a shared content structure for editable DOCX and PDF, preserves section order, and uses readable font fallbacks when the reference fonts are unavailable. Use [Hebrew document guidance](hebrew-documents.md) for native RTL paragraphs and mixed-language checks. Never describe successful conversion alone as visual verification or ATS certification.

Use the relevant PDF or document skill when available. Render the completed artifact and inspect every page for clipping, overlap, broken glyphs, awkward whitespace, orphan headings, and split roles. Re-extract the final PDF text to verify completeness and reading order, including dates, headings, links, and special characters. Check that no sample facts, unsupported claims, placeholders, confirmation tags, or promotional text remain.

Create the requested file when tools support it. If export is unavailable, deliver clean copy or a structured layout specification and explain what could not be produced. Never invent a download link, claim that a document was attached, or describe a merely planned file as complete.
